# ADR 003：星号表示与成功保存基准的内容差异

状态：采用。

## 背景

“曾执行编辑命令”与“当前内容未保存”不是同一含义。用户 undo 回到保存点时，若仍显示星号，会误以为当前文档和磁盘不同。标签插件还需要独立判断祖先容器以及多标签顺序。

## 决策

modified-star 选择**当前内容与最近一次成功 read/save 的基准不同**的语义。成功 read/save 后更新保存基准，失败不更新。init 尚无保存基准，因此根和所有新建节点立即显示 `*`。编辑使内容改变时出现星号；undo 恢复为基准内容后消失；redo 再次改变后出现。将属性设置为原值不制造内容差异。

比较包含节点自身内容、子树结构及子节点顺序；子节点变化使包含它的所有祖先容器行也显示星号，直至 SVG 根。删除节点由剩余祖先的子树差异体现；移动父级或改变排序同样由受影响子树体现。

EditorSession 提供成功保存时的文档快照，专供标签比较；该快照不是 undo 存储，历史仍只保存本次编辑的局部恢复操作。`TreeRow.saved` 和 `EditorSession.saved` 暴露的保存基准遵守**只读使用契约**：插件不得调用其可变领域方法，也不得修改当前文档。这里的只读是插件契约，并非对整个对象图做运行时冻结。modified-star 自己封装保存节点索引与基准引用，缓存仅存在于插件实例字段，不使用模块级共享状态。普通查询、目录读取和统计不改变文档或保存基准。

ViewReceiver 对每行按**装配注册顺序**调用 TreeDecorator，把非空标签用单个空格追加到基础文本。box-type-label 与 modified-star 不感知彼此；相同插件集合、顺序和 options 在 A/B 下得到同样顺序。没有装饰器时，原树输出逐字节保持不变。

## 模式与取舍

TreeDecorator 是按行增加展示信息的扩展接口；当前实现为有序组合，不是完整的经典“Component 同接口递归包装”结构。它借用装饰职责叠加的思想，避免把插件 API 的名字直接当作经典 Decorator 模式的证明。

内容比较使 undo 回到保存点的语义直接且可核验，代价是保存基准及树比较的时间和内存。今天的 CLI 文档规模可接受该成本；不为尚无需求的实时协作或增量索引引入事件系统。未来确有性能证据时，可在插件内部优化比较，保留接口与 dirty 语义。

## 验证

覆盖 init、新建、保存、再次编辑、undo 回保存点、redo、祖先传播、结构删除/排序、失败保存、两个会话状态隔离，以及与 box 标签并存的稳定顺序。实现位于 `src/application/EditorSession.ts`、`ViewReceiver.ts`、`plugins/tree-star/` 和 box 标签类。
