# ADR 004：激活后校验清单，全部成功后原子发布注册项

状态：采用。

## 背景

清单声明不等于插件真的完成注册。如果每次 register 立即修改全局注册表，插件先注册一部分再失败，就会留下无法解释的半加载状态。代码装配和配置装配若绕过不同路径，也难以保证同样行为。

## 决策

两种装配都交给 PluginLoader，再进入同一个 ExtensionRegistry.activate。内核定义 Plugin、PluginContext 与四类扩展契约；宿主负责解析模块、实例来源和 options。代码装配集中在 CodePlugins；配置加载器不导入、映射或分支判断具体插件名称。

一次 activate 使用独立的暂存注册表。注册时检查实例必需方法、稳定名称，以及同一类别内的重复名称；与已发布注册项冲突时拒绝本次插件。激活函数完成后，比较 manifest.contributes 与实际暂存的 shapes、commands、decorators、attributes 名称集合；缺省类别为空，列表顺序不影响集合校验。

只有 activate 成功、清单匹配且所有注册名无冲突，才把四类暂存项一并发布。异步激活后再次检查冲突，避免并发覆盖。激活结束后关闭该 PluginContext，迟到的注册调用拒绝。插件内部捕获重复注册异常也不能把错误“吞掉”后得到半成功激活。

配置整体先校验语法和结构，非法时输出 `error: invalid plugin config`，保留默认内置能力继续启动。有效配置按数组顺序加载，`enabled: false` 完全跳过。options 原样传给 activate，由具体插件校验自己的选项。

模块解析失败、无默认导出、清单不一致、activate 抛错按作业约定报告。先解析顶层模块，再执行 import，可把“顶层模块不存在”和“模块求值或传递依赖失败”区分开。失败插件不影响已成功插件，后续配置仍继续加载。

## 取舍与边界

暂存注册将回滚复杂性留在框架，不要求每个插件编写撤销注册代码；代价是 activate 完成前新能力不可见。清单用于验证公开扩展契约，不是授权机制或安全隔离。事务只覆盖注册表，插件自行写文件、访问网络等外部副作用不在回滚保证内；本项目插件激活仅用于注册。

## 验证

覆盖四种规定失败、重复注册、跨类别部分注册后失败、清单不匹配回滚、吞掉注册异常、迟到注册、已成功插件保留、后续插件继续加载、非法配置降为内置功能，以及 A/B 相同注册路径。实现位于 `src/application/ExtensionRegistry.ts`、`src/host/PluginLoader.ts`、`CodePlugins.ts`。
